# ICM20608 正式接口设计：misc 文本 → IIO sysfs

日期：2026-09-23  
状态：待实现  
相关：`icm20608-module`、`icm20608-read`、`icm20608-logger`、`sensor-dashboard`、设备树 `icm20608@0`

## 目标

将 ICM20608 从板级 **misc `/dev/icm20608` ASCII 行** 改为 Linux 标准 **IIO sysfs** ABI：内核只暴露 raw + scale/offset，物理量换算在用户态；同一镜像内所有消费者一次切完。

## 已确认需求

| 项 | 选择 |
|---|---|
| 一期范围 | 仅 ICM20608 |
| AP3216C | 设计中规划，二期实现 |
| 旧 `/dev/icm20608` | **一把切**，不再保留 misc / 适配层 |
| 一期内核能力 | **仅 IIO sysfs 轮询**（无 DRDY / buffer / trigger） |
| 用户态 | read / logger / Qt 仪表盘同一镜像全部改读 IIO |

## 非目标（一期）

- IIO buffer、trigger、硬件 FIFO、DRDY 中断路径
- 引入完整 `libiio` 依赖（可用轻量自研读 sysfs；二期可再评估）
- 自定义 ioctl / 私有二进制 `/dev` 协议
- 内核内 `sprintf` g/dps/°C
- 同期改造 AP3216C（仅文档预留）

## 方案概览

```
ICM-20608 (SPI CS0)
        │  icm20608 IIO 驱动
        ▼
/sys/bus/iio/devices/iio:deviceN/{*_raw,*_scale,*_offset,name}
        │  板级小库（推荐）或直接读 sysfs
        ▼
icm20608-read / icm20608-logger / sensor-dashboard
```

### 1. 内核驱动

- 去掉 `miscdevice` 与文本 `format_line` / 定点打印辅助函数。
- 实现 `struct iio_dev` + `iio_info`：
  - 通道：`accel` x/y/z、`anglvel` x/y/z、`temp`
  - `read_raw`：对 accel/gyro/temp 返回 `IIO_VAL_INT`（寄存器 burst 读 14 字节）
  - `read_raw` scale：`IIO_VAL_INT_PLUS_MICRO` / `IIO_VAL_FRACTIONAL`（与当前硬件配置一致）
    - Accel ±2g：scale = 1/16384（g / LSB）
    - Gyro ±2000 dps：scale = 2000/32768（或等价 micro）
    - Temp：按 ICM-20608 公式（与现 `temp_raw/326.8+25` 对齐），用 `scale` + `offset`
  - 一期 **不必**实现可写 scale / sampling_frequency（量程仍按现 `hw_init` 固定）；sysfs 只读 scale 即可。文档注明二期可扩展。
- SPI：优先 `spi_write_then_read` 或单帧 duplex；保持 MODE0、8bit。
- 电源：一期可维持 probe 时上电、`remove` 时 sleep；runtime PM / open 引用计数列为后续增强（非一期硬性）。
- `compatible`：一期可继续匹配 `alientek,icm20608`；建议 DT 同时增加或迁移到更标准的 invensense 兼容串（若主线已有则优先对齐，无则保留板级兼容并注释）。
- 内核配置：板级 fragment（如 `board.cfg` 或新 `iio.cfg`）启用 `CONFIG_IIO`、`CONFIG_IIO_BUFFER` 非必须一期；至少 `CONFIG_IIO=y` 与 SPI 客户驱动所需选项。
- Recipe：`icm20608-module` 仍为 out-of-tree 模块；依赖内核 IIO 符号。

### 2. 设备树（一期最小）

现有节点（`ecspi3` / `icm20608@0`）保留 SPI 属性即可。一期 **不强制** 增加中断（无 buffer）。可选清理：确认 `spi-max-frequency`、CS GPIO 与原理图一致。

二期（文档预留）：`interrupts`（DRDY）、`mount-matrix`、`vdd-supply`。

### 3. 用户态 ABI

**发现设备**：遍历 `/sys/bus/iio/devices/iio:device*`，读 `name`，匹配 `icm20608`（或驱动注册的 name）。

**读一次样本**：

1. 读 `in_accel_{x,y,z}_raw`、`in_anglvel_{x,y,z}_raw`、`in_temp_raw`
2. 读对应 `*_scale`（及 temp 的 `in_temp_offset`）
3. 用户态：`value = raw * scale (+ offset)`

推荐新增薄封装（路径示例）：

- `meta-alientek/recipes-apps/common/` 或独立 `libalientek-imu`：`bool readIcmSampleIio(IcmSample *out)`
- `IcmSample` 字段可与现 logger/dashboard 结构对齐（raw + 换算后的 double），避免大改 SQL schema。

**删除**：所有对 `/dev/icm20608` 的 `open`/`read`/`lseek` 及内核文本行 `sscanf`（dashboard 的 `parseIcmSample` 设备路径读法；logger 的 `readDeviceSample` + 文本 parse 可改为结构化填充，单测可测换算而非 sscanf 行）。

`icm20608-read`：CLI 仍可打印人类可读一行（与现输出格式尽量兼容，方便演示），但数据来自 IIO，不是 `/dev`。

环境变量：`ICM20608_DEV_PATH` 改为可选 `ICM20608_IIO_NAME=icm20608` 或直接废弃路径变量；README / default 文件同步。

### 4. 消费者清单（一期必须改）

| 组件 | 改动 |
|------|------|
| `icm20608.c` 驱动 | misc → IIO |
| `icm20608-read` | 读 IIO，打印格式可保留 |
| `icm20608-logger` | 读 IIO 写入 SQLite（表结构可不变） |
| `sensor-dashboard` | `readIcmSample` 走 IIO，去掉对 `/dev/icm20608` 文本依赖 |
| README | 文档改为 IIO 用法 |
| 测试 | 更新/替换依赖 `/dev` 文本的宿主单测 |

Web 若只查 SQLite，可不改服务端 HTML/API；只要 logger 写入字段不变。

### 5. AP3216C 二期预留

- 同样改为 IIO：`in_intensity` / `in_proximity`（或 light + proximity 通道），去掉 `/dev/ap3216c` 文本。
- 用户态统一「按 name 找 iio:device」模式。
- 不与一期混在同一实现 PR 硬绑定，但命名与发现逻辑应可复用。

### 6. 实现顺序

1. 内核 IIO 驱动 + 确认 `CONFIG_IIO`
2. 用户态公共读 IIO 辅助（或直接在各 app 内先实现一处再抽）
3. 改 `icm20608-read` → logger → dashboard
4. 删除 misc 残留；更新 README / default / 测试
5. 板上验证

### 7. 验证

- `ls /sys/bus/iio/devices/*/name` 可见 `icm20608`
- `cat .../in_accel_z_raw` 静止约对应 ±1g（结合 scale）
- `icm20608-read` / `-w` 输出合理
- logger 持续写入；Web 六轴页有新点
- Qt 仪表盘六轴卡片/详情正常
- 镜像中 **无** `/dev/icm20608`（或节点不存在）

### 8. 风险

| 风险 | 对策 |
|------|------|
| IIO 未编进内核 | board fragment 显式 `CONFIG_IIO=y` |
| scale 单位与旧演示不一致 | 对照现有定点公式做对照表与板上对比旧固件读数 |
| name 冲突 / 多 IIO 设备 | 按 `name` 匹配，不写死 `iio:device0` |
| 出树模块与 IIO API 版本 | 针对当前 scarthgap/linux 7.2 头文件编写 |

## 成功标准

- 产品 ABI 为 IIO sysfs，不再依赖私有 misc 文本行。
- 阿尔法现有演示链路（串口 read、logger、Web、LCD 仪表盘）在新接口下行为等价。
- AP / buffer 不阻塞一期合并。
