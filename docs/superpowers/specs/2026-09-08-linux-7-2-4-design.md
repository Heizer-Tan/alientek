# Linux 7.2.4 升级设计

## 目标

将当前板级内核从 `kernel.org Linux 7.1.4` 升级到 `kernel.org Linux 7.2.4`，并保持仓库表达一致：配方命名、版本字段、源码下载地址、校验信息和文档说明同步切换到 `7.2.4`。

## 范围

- 新增或重命名内核 recipe 为 `meta-alientek/recipes-kernel/linux/linux_7.2.bb`
- 更新 recipe 内的 `DESCRIPTION`、`LINUX_VERSION`、`PV`、`SRC_URI` 和源码校验信息
- 搜索并修正仓库内对 `7.1.4` 和 `linux_7.1.bb` 的直接引用
- 同步更新用户可见文档中的内核版本描述
- 做最小必要验证，确认新 recipe 能被 BitBake 识别，并尽量验证内核目标构建可启动

## 不做的事

- 不改 U-Boot 版本
- 不改设备树功能逻辑
- 不借这次升级顺手重构内核 recipe 体系
- 不扩展 MQTT OTA 方案范围

## 设计决策

### 配方命名

采用独立的 `linux_7.2.bb`，不保留 `linux_7.1.bb` 作为实际生效配方。

原因：

- 文件名和真实版本保持一致，降低维护歧义
- 后续继续升级时，搜索版本引用更直观

### 源码来源

直接对齐 `kernel.org 7.2.4` 正式发布版本，更新下载 URL 和对应校验值，避免“版本号已改但源码仍旧版本”的不一致状态。

### 引用同步

除配方本身外，还需要同步检查：

- `README.md`
- `docs/board-function-overview.md`
- 可能写死 recipe 名或版本号的计划/说明文件

说明类文档如果只是历史记录，可视情况保留；但面向当前实现状态的说明必须更新到 `7.2.4`。

## 验证

优先执行：

- 搜索确认仓库内不再错误引用当前生效版本为 `7.1.4`
- 运行最小构建验证，确认 `linux_7.2.bb` 可被识别

建议执行：

- `./scripts/build.sh virtual/kernel`

如果全量内核构建耗时过长，至少完成 recipe 解析和目标构建入口验证，并在结果里明确说明验证深度。

## 风险

- 上游小版本升级可能带来补丁、配置或设备树兼容性变化
- 若仓库中存在对旧 recipe 文件名的隐式引用，重命名后会暴露出来
- 文档若漏改，容易导致“实际版本”和“说明版本”不一致

## 实施结果标准

- 生效配方名称与版本一致，为 `linux_7.2.bb`
- recipe 指向 `kernel.org Linux 7.2.4`
- 当前说明文档中的主版本描述同步为 `7.2.4`
- 至少完成一轮可复现的构建级验证并记录结果
